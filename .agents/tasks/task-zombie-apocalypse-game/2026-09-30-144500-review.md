# OBJ_WAKE soft-lock fix, zone disposal, and real-path win hook (v2)

The follow-up commit (`cfcb97d`) closes the blocking soft-lock from v1 and the four secondary issues. `OBJ_WAKE` now advances on a real player action — crossing the room doorway fires `left_room`, with the first `zombie_killed` as a doorway-fight fallback — so normal play reaches `OBJ_SURVIVE` and the rest of the cure loop without touching a test hook. The story-completion hooks (`collectAllIngredients`, `_forceWin`) were re-routed to drive the same real events a player triggers instead of silent `advanceTo` jumps, `Zone.dispose()` frees geometries and materials on unload/travel/restart, `QuestManager` now owns `requiredIngredients` as its single source of truth, and the `main.js` error filter was narrowed to specific gesture-rejection wordings.

Watch for: nothing blocking. The full player path advances `OBJ_WAKE → OBJ_SURVIVE` on doorway crossing and on the first kill, the real-event win hook reaches `WIN` with the correct end state (zone `MedicalFacility`, gun, 3 ingredients), `triggerLose` reaches `LOSE`, and travel/restart cycles disposing both zones produce no console errors (all confirmed via the headless harness).

**Verdict**: APPROVED

## High-level view

The opening transition is now driven by real gameplay. `OdishaCity.update` watches the player's z-position each frame and fires `onLeaveRoom` once when they cross south of the doorway (`z < doorwayZ - 0.5`); `QuestManager` advances `OBJ_WAKE → OBJ_SURVIVE` on that `left_room` event, and also on the first `zombie_killed` (counting the kill) so a player who fights in the doorway before crossing it isn't stranded. The doorway geometry is consistent — the player wakes at z=3, the doorway sits at z=-6, and the city lies further south — so the trigger requires a genuine traversal.

The verification hooks no longer diverge from the player path at the broken step. `_collectAllIngredients` fires `left_room`, then real `zombie_killed` events until `OBJ_SURVIVE` clears, then the real gun/talk/research events; `_forceWin` chains that into a real `travelTo` and real `deliver`/`board_helicopter` events, relying on the `board_helicopter → onWin → WIN` chain rather than forcing the state. The harness now exercises the same transitions a player does.

`Zone.dispose()` traverses the group disposing every geometry and material and resets the entity/collider bookkeeping with `_built=false`, invoked from `unload`. Textures are deliberately left alone because `AssetFactory` shares cached texture objects across zones and rebuilds — disposing them would corrupt the copy still in use. The reasoning is documented at the dispose site.

`requiredIngredients` is set from `REQUIRED_INGREDIENTS` in `reset()`, and `Game` reads it directly with the `?:3` fallback removed, so the goal has one source of truth. The pointer-lock error filter dropped the broad `/Pointer Lock/i` catch-all for four specific gesture-rejection patterns, so a future non-benign error mentioning pointer lock is no longer silently swallowed.

### OBJ_WAKE now advances on a real player action

The v1 blocker — nothing advanced `OBJ_WAKE`, freezing the entire story in normal play — is closed by two real triggers. `OdishaCity.update(dt, ctx)` reads `ctx.player.group.position.z` each frame and, once it drops below `doorwayZ - 0.5`, sets `_leftRoom = true` and calls `onLeaveRoom()`, which the `Game` wires to `quest.handleEvent({ type: 'left_room' })`. `QuestManager` advances `OBJ_WAKE → OBJ_SURVIVE` on that event. The `zombie_killed` case now also advances out of `OBJ_WAKE` (and counts the kill toward `SURVIVE_KILLS`), covering a player who kills a zombie reaching through the doorway before physically crossing it.

The geometry backs this up as a real traversal rather than a trigger that fires at spawn: the player wakes at `default: { x:0, z:3 }`, `makeRoom` puts the doorway on the `-Z` wall at `z = -ROOM_SIZE/2 = -6`, and the city buildings sit at negative z beyond that. Confirmed in the harness: starting a fresh game reports `objectiveId: "OBJ_WAKE"`; moving the player to `z=-8` and ticking one frame flips `_leftRoom` to `true` and the objective to `OBJ_SURVIVE`; and from a fresh `OBJ_WAKE`, a single `zombie_killed` event yields `{ obj: "OBJ_SURVIVE", kills: 1 }`.

`_leftRoom` is a one-shot latch set in the constructor. It correctly persists as `true` across a travel-away-and-return to Odisha (OBJ_WAKE is already behind the player, so the doorway shouldn't re-fire), and `_restart()` builds fresh zone instances so it resets to `false` — both verified, with the objective reading `OBJ_SURVIVE` after the round trip.

### Win hook drives the real event chain

`_collectAllIngredients` and `_forceWin` no longer step over the opening transition. The collect hook fires `left_room`, loops real `zombie_killed` events (guarded at 100 iterations) until `OBJ_SURVIVE` clears, then fires the real gun pickup, `talk_survivor`, and `enter_research` events before granting ingredients through real `pickup` events up to `requiredIngredients`. `_forceWin` calls that, then `travelTo('MedicalFacility')` (which itself emits the `travel` event and swaps zones), then real `deliver` and `board_helicopter` events. The forced `advanceTo('WIN')` and direct `setState(GameState.WIN)` from v1 are gone; the win now flows through `board_helicopter → onWin`.

`triggerWin` reaches `state: "WIN"` with `objectiveId: "WIN"`, `zone: "MedicalFacility"`, `weapon: "gun"`, and `ingredients: 3` — the expected end state through the real chain. `triggerLose` reaches `LOSE`. No console errors in either path.

### Zone disposal frees GPU resources, textures deliberately spared

`unload` now calls `dispose()`, which traverses `this.group`, disposing each mesh geometry and material (handling material arrays), then clears the group and resets `colliders/zombies/npcs/pickups/exits/interactables/spawns` and `_built` so a later `load()` rebuilds cleanly. Textures are intentionally not disposed:

```
AssetFactory._textureCache  ──shares same texture object──►  OdishaCity meshes
                            └─────────────────────────────►  MedicalFacility meshes
                            └─────────────────────────────►  every rebuilt zone
```

Disposing a cached texture here would corrupt the copy still bound in the other zone or the next rebuild; geometries and materials are created fresh per mesh and are safe. The reasoning is captured in the dispose comment. Travel Odisha→Medical→Odisha and a full `_restart()` — each disposing and rebuilding zones — leave the game in a valid `PLAYING` state with Odisha rebuilt (`_built:true`, 8 zombies, 62 colliders) and no console errors.

### requiredIngredients single source of truth

`QuestManager.reset()` sets `this.requiredIngredients = REQUIRED_INGREDIENTS`, and `Game._collectAllIngredients` reads `q.requiredIngredients` directly with the v1 `?:3` fallback removed. The duplicated literal that would have drifted if the constant changed is gone.

### Pointer-lock error filter narrowed

`main.js` dropped the broad `/Pointer Lock/i` pattern for four specific gesture-rejection wordings (`user gesture is required...`, `request(?:ed)? Pointer Lock without ... user gesture`, `pointer lock (?:was )?denied`, `Unable to use Pointer Lock`). A future error that merely mentions pointer lock but isn't one of these benign rejections will now surface to the harness instead of being swallowed. Across every scenario run (init, start, doorway crossing, kill fallback, full win, lose, travel cycles, restart) `window.__consoleErrors` stayed empty.
