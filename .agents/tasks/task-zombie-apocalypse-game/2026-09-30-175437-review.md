# Bundled character models and realistic environment pass (v3)

This change replaces block-built characters with a bundled animated hazmat zombie and rigged human base, retaining procedural fallbacks when either GLB cannot load. It adds a preload screen, per-instance animation and ownership handling, denser PBR-style procedural terrain/buildings/props, and refreshed screenshots. The visual pass leaves quest callbacks, pickups, exits, and collision topology in place, and the complete cure-to-helicopter loop remains playable with imported models or fallbacks. Every runtime resource still resolves from the static site's own origin.

## High-level view

Startup waits for `ModelLibrary` to settle both same-origin GLB requests before constructing the synchronous world. Each request independently falls back to the procedural character path, so one or both unavailable models do not block the start screen.

Zombie clones isolate skeletons, geometries, and materials while sharing imported textures; human clones add owned clothing and use bone-rest animation because the source has no clips. Horizontal hip motion is stripped from zombie clips, wrappers establish a ground pivot and local +Z facing, and entity states continue to select idle, walk, and attack presentation.

Roads, sidewalks, medical hardstanding, richer facades, props, and atmosphere remain visual children of the existing zones. Travel and restart release owned resources, rebuild the same entity/trigger/collider sets, and preserve the approved room-exit and win event paths.

Observed runtime requests stayed on the serving origin, and both GLBs contain their buffers and images. **Confirmed attribution mismatch:** detailed credits correctly classify Zombie Hazmat as CC BY 4.0 and Male Base Mesh as CC0 1.0, but the README overview calls both files CC-BY.

### Per-model preload failure falls back without blocking startup

`main.js` installs diagnostics before loading modules and waits for `preloadCharacterAssets()` before constructing `Game`. `ModelLibrary` catches each `GLTFLoader.loadAsync` failure separately and resolves with that key marked for fallback, preserving the factory's synchronous API. With both GLB routes forced to return 404, bootstrap reached `READY`, reported two fallbacks, built the original 8-zombie/5-NPC Odisha population, and completed `triggerWin()` in the Medical Facility with all three ingredients. The normal run loaded both assets; its resource entries were all same-origin, and the GLBs contained no remote URI.

### Character clones isolate mutable rig state and authored motion

`SkeletonUtils.clone` creates a skeleton per instance, and `setMeshQuality` clones each mesh geometry and material. Imported maps remain shared and unmarked for disposal, while generated tiled texture clones are subtree-owned. Runtime inspection confirmed separate geometry, material, and skeleton objects across zombie and human instances, with only imported zombie maps shared.

All requested zombie actions resolved, and every clip's hip-position track had constant X/Z values after preload, leaving translation to the AI wrapper. The human adapter found all 18 expected bones. Sampled rendered bounds were approximately 1.88 m for a zombie and 1.76 m for a human; controlled updates selected `walk` while chasing and `attack` at contact range.

```
preloaded template ── shared clips/textures (retained)
        │
        ├─ clone A ── own skeleton/geometry/material ── disposed with entity
        └─ clone B ── own skeleton/geometry/material ── disposed independently
```

Entity teardown uncaches its mixer before releasing the instance subtree. Zone-level defensive disposal is guarded by weak sets; an observed imported zombie geometry and material each emitted exactly one disposal event during Odisha unload.

### Zone rebuilds preserve quest topology and bounded resources

The new surfaces and rubble do not replace gameplay coordinates. Odisha still rebuilds with 8 zombies, 5 NPCs, 62 colliders, 3 initial pickups, 1 exit, and 1 interactable; Medical rebuilds with 8 zombies, 3 NPCs, 13 colliders, and 2 interactables.

An Odisha → Medical → Odisha → Medical round trip rebuilt the same zone instances with those counts and no captured errors. Three full win/restart cycles returned renderer memory to 617 geometries and 45 textures at each fresh Odisha start, reset room/research/ingredient flags, and returned to `OBJ_WAKE`; crossing the doorway then advanced to `OBJ_SURVIVE`. Imported-model and forced-fallback runs both reached `WIN` through the existing quest event chain.
